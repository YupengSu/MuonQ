Overview

Where 4-bit Muon loses its direction

Muon updates the weights with the polar factor of its momentum: it keeps every direction of the momentum and gives each one the same strength. A 4-bit copy of the momentum therefore only has to point the right way. Step through one real layer to see where plain 4-bit storage fails and how MuonQ avoids it.

MuonQ in three changes

Muon trains language models with less compute than Adam by orthogonalizing its momentum before every update. Its optimizer state is one momentum matrix per layer, so storing that matrix in 4 bits would remove most of the optimizer's memory. But Muon is unusually sensitive to quantization: the polar step keeps only the directions of the momentum, and small rounding errors in those directions grow in the update.

MuonQ quantizes for directional fidelity, measured by cosine similarity, instead of numerical closeness. It makes one change at each point where error enters a training step.

Method

One MuonQ training step

MuonQ changes how the momentum is normalized and stored between steps. Each step reads the 4-bit state, adds the new gradient, and writes the state back in 4 bits. The weight update is still Muon's polar step, applied to the current step's full-precision momentum.

What the optimizer stores

Muon state for GPT-2 Small (Tables 4 and 9)

The extra factors U and S cost 3.8 MB on top of plain 4-bit storage. Step time on LLaMA-1.1B is 10.7% above full-precision Muon.

1
Step 1 · before quantizing

Normalize the gradient and the momentum

Problem
A 4-bit scale follows the largest values, so each step's rounding error grows and shrinks with the gradient norm. Over many steps these errors add up and drift in one direction.
Fix
Scale the gradient and the momentum to unit Frobenius norm before quantizing. Every step then adds an error of the same size, and the errors stay balanced instead of piling up.

Normalization costs no memory. Added to full-precision Muon it barely changes the loss curve (see the ablation), so its benefit comes from how rounding error accumulates.

2
Step 2 · splitting the momentum

Store the strongest directions separately

Problem
With one scale for the whole matrix, the weak directions sink into rounding error. The polar step then gives those noisy directions full weight, as the figure at the top shows.
Fix
Split the momentum into its top-k singular directions and a small residual, using one warm-started power-iteration step. Each direction gets its own 4-bit scale: U per column, S per row.

An error inside one direction's own group mostly changes how strong that direction is, and the polar step resets every strength anyway. The residual R holds what is left; it is small, so its single scale is fine-grained. With k = min(m, n)/16 the factors add 9% memory on GPT-2 Small.

3
Step 3 · writing the 4-bit codes

Spend the levels where the values are

Problem
Momentum values crowd around zero with a few large outliers. Evenly spaced 4-bit levels stretch to cover the outliers, so the dense center gets only a few levels and many small values collapse onto the same code.
Fix
Apply μ-law companding before rounding, with μ = 255 as in G.711 telephone audio. It packs levels near zero, where most values sit, and spreads them out in the tails.
Results

4-bit training that tracks full precision

We pre-train GPT-2 Medium and Large and LLaMA-350M and 1.1B on FineWeb (5 to 13.1 billion tokens) with the standard Muon recipe on A100 GPUs. Muon32 is full precision, Muon8 and Muon4 store the momentum with plain 8- and 4-bit quantization, and MuonQ4 is our method.

MuonQ4 follows Muon32 from the first steps. Plain Muon4 never closes its gap, and the gap grows with model size.

The dashed MuonQ4 curve closely follows Muon8, which uses twice as many bits per value. On LLaMA-1.1B the validation perplexity is 12.67 for MuonQ4, 12.42 for Muon8, 11.47 for Muon32 and 23.18 for plain Muon4.

Perplexity and optimizer memory

Zero-shot accuracy

Average over ARC-c, ARC-e, OBQA, BoolQ, HellaSwag, PIQA and WinoGrande. MuonQ4 trails Muon32 by about one point on average and recovers most of what plain 4-bit loses.

Against GRASP on LLaMA-1.1B

GRASP keeps part of its state in 8 bits. Under identical training settings, pure 4-bit MuonQ4 saves more memory (7.28× against 6.02×) at a perplexity 0.34 higher. Both add about 10% to the step time.

Code

Train with MuonQ

The repository has the optimizer, Hydra configs for the GPT-2 and LLaMA models in the paper, and the FineWeb preprocessing script.

Set up and train bash

git clone https://github.com/YupengSu/MuonQ && cd MuonQ
pip install -r requirements.txt   # after installing PyTorch for your CUDA
cp .env.example .env               # set DATA_DIR and HF_HOME

# tokenize FineWeb with the LLaMA tokenizer
python process_data.py --name fineweb100B --tokenizer llama2

# GPUs, optimizer config, model recipe
bash run.sh 0,1,2,3 muonq llama-60m

Optimizer config hydra_conf/optimizer_params/muonq.yaml

name: muonq
args:
  lr: 0.001
  weight_decay: 0.1
  polar_method: Keller   # Newton-Schulz, 5 steps
  ns_steps: 5
  qbit: 4                # 4-bit state
  gran: tensor           # residual R: one scale
  compand: True          # step 3, μ-law
  norm: True             # step 1, unit norm
  rank: 16               # step 2, k = min(m, n) / 16
