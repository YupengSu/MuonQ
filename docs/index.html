MuonQ

Enhancing Low-Bit Muon Quantization via Directional Fidelity Optimization

MuonQ keeps the Muon optimizer's momentum in 4 bits without losing the direction of its updates.

Method

Muon keeps only the directions of its momentum. MuonQ stores that momentum in 4 bits so the directions survive.

The problem

Rounding error that the polar step amplifies

Muon updates the weights with the polar factor of its momentum. It keeps every singular direction and gives each the same strength:

𝐖t=𝐖t−1−ηpolar(𝐌t)\mat{W}_t = \mat{W}_{t-1} - \eta \, \mathrm{polar}(\mat{M}_t)

Scale drops out of the polar factor, polar(α𝐌)=polar(𝐌)\mathrm{polar}(\alpha\mat{M}) = \mathrm{polar}(\mat{M}), so the part of a 4-bit error that lies along 𝐌\mat{M} is harmless. Only the part orthogonal to 𝐌\mat{M} reaches the update, and its size, ‖𝐌ˆ‖F1−CS2\|\hat{\mat{M}}\|_F \sqrt{1 - \mathrm{CS}^2}, is set by the cosine similarity of the copy:

CS(𝐌,𝐌ˆ)=⟨𝐌,𝐌ˆ⟩F‖𝐌‖F⋅‖𝐌ˆ‖F\mathrm{CS}(\mat{M}, \hat{\mat{M}}) = \frac{\langle \mat{M},\, \hat{\mat{M}} \rangle_F}{\|\mat{M}\|_F \cdot \|\hat{\mat{M}}\|_F}

MuonQ therefore optimizes this directional fidelity instead of the relative error (RE), which also counts the harmless part. Every CS on this page compares a 4-bit result with full precision; 1 means the same direction.

A plain 4-bit copy of the momentum still has a CS of 0.994. But its weak directions are mostly rounding error, and the polar step lifts them to full strength.

NNormalize

Give every step the same rounding error

Problem. A 4-bit scale follows the largest value, so each step's error grows and shrinks with the gradient norm. Over many steps the errors add up in one direction.

Fix. Scale the gradient and the momentum to unit norm before quantizing:

𝐌t=β𝐌ˆt−1+𝐆t‖𝐆t‖F,𝐌¯t=𝐌t‖𝐌t‖F\mat{M}_t = \beta \hat{\mat{M}}_{t-1} + \frac{\mat{G}_t}{\|\mat{G}_t\|_F}, \quad \bar{\mat{M}}_{t} = \frac{\mat{M}_{t}}{\|\mat{M}_{t}\|_F}
0.16→0.90CS of the 4-bit momentum after 50 steps, without → with normalization
DDecompose

Give each strong direction its own scale

Problem. With one scale for the whole matrix, the weak directions sink into rounding error, and the polar step gives them full weight.

Fix. Split off the top-kk singular directions with one warm-started power step. 𝐔\mat{U} gets a scale per column, 𝐒\mat{S} per row; the small residual 𝐑\mat{R} shares one:

𝐌¯t=𝐔t𝐒t+𝐑t,\bar{\mat{M}}_t = \mat{U}_t \, \mat{S}_t + \mat{R}_t, 𝐔t=orth(𝐌¯t𝐕t−1⊤),𝐒t=𝐔t⊤𝐌¯t\mat{U}_t = \mathrm{orth}(\bar{\mat{M}}_t \, \mat{V}_{t-1}^{\!\top}), \quad \mat{S}_t = \mat{U}_t^{\!\top}\,\bar{\mat{M}}_t
0.674→0.982CS of the update after the polar step, without → with decomposition

k=min⁡(m,n)/16k = \min(m, n)/16 for every layer: 9.4% more optimizer memory on GPT-2 Small. 𝐕t−1\mat{V}_{t-1} is 𝐒ˆt−1\hat{\mat{S}}_{t-1} with unit rows.

CCompand

Spend the 15 levels where the values are

Problem. Momentum values crowd around zero with a few large outliers. Evenly spaced levels stretch to cover the outliers and leave the dense center only a few codes.

Fix. Compress with μ-law before rounding and expand after, which packs the levels near zero:

f(x)=sgn(x)ln⁡(1+μ|x|)ln⁡(1+μ),μ=255f(x) = \mathrm{sgn}(x)\,\frac{\ln(1 + \mu\,|x|)}{\ln(1 + \mu)}, \quad \mu = 255
0.879→0.973CS of the 4-bit momentum on layers.0.self_attn.k_proj with one scale, even → μ-law levels (Table 1)

Per row 0.992 → 0.994, per column 0.969 → 0.988: μ-law helps at every grouping.

Results

GPT-2 Medium and Large and LLaMA-350M and 1.1B, pre-trained on FineWeb (5–13.1B tokens) with the standard Muon recipe. Muon32 is full precision, Muon8 and Muon4 plain 8- and 4-bit storage, MuonQ4 is MuonQ.

Memory and quality

4-bit memory, close to 8-bit quality

7.28×less optimizer-state memory than Muon32 on LLaMA-1.1B, 4.50 → 0.62 GB
23.18→12.67LLaMA-1.1B validation perplexity, plain 4-bit → MuonQ4; Muon8 reaches 12.42, Muon32 11.47
90%of the perplexity gap between Muon4 and Muon32 closed on LLaMA-1.1B
Training

Tracks full precision from the first steps

MuonQ4 follows Muon32 and stays close to Muon8, which uses twice the bits. Plain Muon4 never closes its gap, and the gap grows with model size.

Fig. 5 of the paper, in the paper's colors (Muon4 yellow, MuonQ4 red dashed). Click the plot to enlarge it.

Downstream

About one point behind full precision

≈ 1ptaverage zero-shot accuracy behind Muon32 over seven tasks and four models

MuonQ4 recovers 71–88% of what plain 4-bit storage loses. Tasks: ARC-c, ARC-e, OBQA, BoolQ, HellaSwag, PIQA and WinoGrande.

Ablation

Each change earns its place

69.9→40.9GPT-2 Small perplexity, plain 4-bit → all three changes; Muon32 reaches 36.4

Decomposition gives the largest single gain and costs 3.8 MB of extra state; normalization and companding cost nothing.

Code

The repository has the optimizer, Hydra configs for the GPT-2 and LLaMA models in the paper, and the FineWeb preprocessing script.

Set up and train
git clone https://github.com/YupengSu/MuonQ && cd MuonQ
pip install -r requirements.txt   # after installing PyTorch for your CUDA
cp .env.example .env               # set DATA_DIR and HF_HOME

# tokenize FineWeb with the LLaMA tokenizer
python process_data.py --name fineweb100B --tokenizer llama2

# GPUs, optimizer config, model recipe
bash run.sh 0,1,2,3 muonq llama-60m
Optimizer config hydra_conf/optimizer_params/muonq.yaml
name: muonq
args:
  lr: 0.001
  weight_decay: 0.1
  polar_method: Keller   # Newton-Schulz, 5 steps
  ns_steps: 5
  qbit: 4                # 4-bit state
  gran: tensor           # residual R: one scale
  compand: True          # C, μ-law
  norm: True             # N, unit norm
  rank: 16               # D, k = min(m, n) / 16
