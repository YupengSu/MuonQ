Where 4-bit Muon loses its direction

Method

Muon updates the weights with the polar factor of its momentum: it keeps every direction of the momentum and gives each the same strength. A 4-bit copy of the momentum therefore has to point the right way, not just be numerically close. MuonQ keeps Muon's update and changes how the momentum is normalized, split and rounded each time it is stored in 4 bits:

Wt=Wt−1−η·polar(M¯t)

  1. 1Normalize the gradient and the momentum

    A 4-bit scale follows the largest values, so each step's rounding error grows and shrinks with the gradient norm, and over many steps the errors drift in one direction. MuonQ scales the gradient and the momentum to unit Frobenius norm before quantizing, so every step adds an error of the same size:

    Mt=βMˆt−1+Gt‖Gt‖F,M¯t=Mt‖Mt‖F

    Error of the stored momentum against the full-precision trajectory over 50 steps of plain 4-bit storage, traced from Fig. 1 of the paper. On full-precision Muon the normalization leaves the loss curve unchanged (mean absolute difference 0.003), so its gain comes from how rounding error accumulates.

  2. 2Store the strongest directions separately

    With one scale for the whole matrix, the weak directions sink into rounding error and the polar step gives them full weight, as in the first figure. MuonQ splits off the top-k singular directions with one warm-started power-iteration step and gives each its own 4-bit scale, U per column and S per row; the small residual R shares one scale:

    M¯t=UtSt+Rt, Ut=orth(M¯tVt−1⊤),St=Ut⊤M¯t, Vt−1=RowNorm(Sˆt−1)

    Schematic on a 10 × 16 matrix with k = 3. MuonQ uses k = min(m, n)/16 for every layer, which adds 9.4% optimizer memory on GPT-2 Small.

  3. 3Spend the 4-bit levels where the values are

    Momentum values crowd around zero with a few large outliers, so evenly spaced levels stretch to cover the outliers and leave the dense center only a few codes. MuonQ applies μ-law companding before rounding and its inverse after, which packs the levels near zero:

    f(x)=sgn(x)·ln(1+μ|x|)ln(1+μ),μ=255

    The histogram is a synthetic 512 × 512 momentum with heavy tails (Student-t, 6 degrees of freedom), scaled to unit Frobenius norm as in MuonQ; its numbers land close to the real layer, layers.0.self_attn.k_proj, in Table 1. μ-law helps at every grouping.

Algorithm 1: one full MuonQ step

Input: gradient Gt, learning rate η, momentum β, rank k, weights Wt−1, and the 4-bit state (U, S, R) written by the previous step.

1read  Mt−1 ← U S + Rdequantize; zero at t = 1
1Normalize
2Mt ← β Mt−1 + Gt / ‖Gt‖F
3Mt ← Mt / ‖Mt‖Funit-norm momentum
2Split off the top-k directions
4V ← RowNorm(S);  Ut ← orth(Mt V⊤)one warm-started power step
5St ← Ut⊤ Mt;  Rt ← Mt − UtSt
3Compand and store in 4 bits
6store  CQuant(Ut) per column, CQuant(St) per row, CQuant(Rt) per tensor
→Update the weights, as in Muon
7Wt ← Wt−1 − η · polar(Mt)

Results

GPT-2 Medium and Large and LLaMA-350M and 1.1B are pre-trained on FineWeb (5 to 13.1 billion tokens) with the standard Muon recipe on A100 GPUs. Muon32 is full precision, Muon8 and Muon4 store the momentum with plain 8- and 4-bit quantization, and MuonQ4 is MuonQ.

  • 4.50 0.62 GBoptimizer state of LLaMA-1.1B: 7.28× less than full-precision Muon, with every stored factor in 4 bits
  • 23.18 12.67LLaMA-1.1B validation perplexity, plain 4-bit Muon → MuonQ4; 8-bit Muon reaches 12.42 and full precision 11.47
  • ≈ 1 pointof average zero-shot accuracy behind full-precision Muon, over seven tasks and four models

Values from Fig. 6 of the paper; Table 3 lists the LLaMA-1.1B memory as 4.50, 1.13, 0.56 and 0.62 GB, and the ratios agree.

Training loss

MuonQ4 follows Muon32 from the first steps and closely tracks Muon8, which uses twice as many bits per value. Plain Muon4 never closes its gap, and the gap grows with model size.

Against GRASP on LLaMA-1.1B

GRASP keeps part of its state in 8 bits. Under identical training settings, pure 4-bit MuonQ4 saves more memory (7.28× against 6.02×) at a perplexity 0.34 higher; both add about 10% to the step time (Table 3).

Code

The repository has the optimizer, Hydra configs for the GPT-2 and LLaMA models in the paper, and the FineWeb preprocessing script.

Set up and train
git clone https://github.com/YupengSu/MuonQ && cd MuonQ
pip install -r requirements.txt   # after installing PyTorch for your CUDA
cp .env.example .env               # set DATA_DIR and HF_HOME

# tokenize FineWeb with the LLaMA tokenizer
python process_data.py --name fineweb100B --tokenizer llama2

# GPUs, optimizer config, model recipe
bash run.sh 0,1,2,3 muonq llama-60m
Optimizer config hydra_conf/optimizer_params/muonq.yaml
name: muonq
args:
  lr: 0.001
  weight_decay: 0.1
  polar_method: Keller   # Newton-Schulz, 5 steps
  ns_steps: 5
  qbit: 4                # 4-bit state
  gran: tensor           # residual R: one scale
  compand: True          # step 3, μ-law
  norm: True             # step 1, unit norm
  rank: 16               # step 2, k = min(m, n) / 16
